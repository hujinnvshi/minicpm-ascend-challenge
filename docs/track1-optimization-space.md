# 910C 优化空间分析（2026-08-01）

> ⚠️ 2026-08-04 修订：实际评测环境为 910B3（替代 910C）。本文 910C 侧预期需按 910B 折算：
>   - 图模式 USE_ACL_GRAPH：910B 不支持（删除下方第 3 项杠杆）
>   - 算力：单卡 910B ≈ 半颗 910C，RTF 预期 0.55-0.65 需上调
>   - Q8_0 复活 / 大 ctx / 量化重扫 三项在 910B 上仍成立，照测
>   完整环境基线见 docs/env-scan.md

> 背景：4090 已收敛（Q4_K_M + ctx8192 = RTF 0.75），剩余提升空间主要在 910C 侧。
> 前提：正式数据每配置 3 次取一致值；每次必须配 llm_debug 输出质量检查（防 CANN 版乱码坑）。

## 一、4090 侧剩余空间（小，边际收益低）

| 项 | 预期 | 说明 |
|---|---|---|
| n_batch 4096 | ±2% | 影响 prefill 段，当前默认 2048 |
| stream-interval/chunk 节奏 | 小 | 官方 perf 固定测法，可变空间有限 |
| token2wav_device 切 CPU | 未测 | GPU 留给 LLM/TTS 的数据流优化 |
| 合计预期 | 0.75 → ~0.70 | 不值得为它烧 4090 卡时 |

## 二、910C 侧空间（按杠杆排序）

1. **硬件算力**（确定性收益）
   910C ≈ 1.5-2x 4090，LLM 段自然加速 → RTF 粗估 0.55-0.65
   注意：量化对 LLM 段收益小 → LLM 段占比不高，算力增益被稀释

2. **Q8_0 复活**（潜在最大单项，0.32 在 CUDA 是 bug 不是性能）
   - CUDA 后端重复 token 乱码 bug → 0.32 为虚假性能
   - CANN 无此 bug 则 INT8 精度损失通常 ≤2pp 大概率安全
   - 若正常 → RTF 0.3-0.4 量级，可能达夺冠级差距
   - ⚠️ 必须实测 + llm_debug 文本校验

3. **图模式 USE_ACL_GRAPH**（未验证大杠杆）
   - TTS/Token2Wav 小算子密集，整图下发省调度开销，此段收益最明显
   - 910C 编译 --graph 变体对比

4. **大 ctx**（910C 显存 64G+）
   - LLM 训练 ctx 40960，4090 只敢 8192；910C 试 16384/32768
   - 4090 趋势：ctx 越大越快（2048→8192 持续变好），910C 可能延续

5. **量化档重扫**（CANN 算子行为不同）
   - Q4_K_M 是 CUDA 最优，CANN 上不一定——六档重测（每档 3 次）

## 三、天花板

- 下限由 TTS/Token2Wav 波形合成计算本身决定（算法层面，超出比赛范围）
- 910C 合理预期 0.3-0.5；0.3 以下需 Q8_0 复活 + 图模式 + 大 ctx 三者同时成立

## 四、910C 验证顺序（建议）

1. 编译（含 --graph 变体）：build-cann.sh / build-cann.sh --graph
2. 基线：Q4_K_M + ctx8192（预期 0.55-0.65）
3. Q8_0 质量检查（若正常 → 最大收益）
4. 大 ctx 扫描（16384/32768）
5. 六档重扫确认
全程：llm_debug 输出检查 + capture-env.sh 采集

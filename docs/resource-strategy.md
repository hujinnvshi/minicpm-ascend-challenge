# 算力资源利用策略

更新：2026-07-31
资源：本地 secs 4×4090 D（GPU1 可用 ~14G）+ 官方 HiDevLab 910C（100 卡时）

## 核心原则

4090 干所有"试错"，910C 只干"验证 + 正式数据"。
CUDA 与 CANN 后端的推理链路/CLI 参数/benchmark 方法/量化档位/大部分
运行时参数通用，参数搜索空间 90% 可平移。

## 分工

### 本地 4090（免费，承担 ~90% 工作量）
1. 全流程跑通：模型加载、文本/视觉/TTS 链路、CLI 参数
2. 量化档位第一轮扫描：Q8_0/Q6_K/Q5_K_M/Q4_K_M/Q4_K_S/Q3 → 筛出 2-3 档候选
3. 运行时参数搜索：ctx-size、线程、chunk、KV cache、滑动窗口 stride
4. benchmark 脚本开发与验证（输入集、统计方法）
5. Demo 链路验证（llama-omni-server + 前端，C++ 后端同架构）
6. 精度初筛（Q8_0 输出当参考对比各档）
7. 演示视频录制

### 官方 910C（100 卡时，只做 4 件事）
1. 环境验证 + CANN 版编译 + 官方基线 RTF
2. 4090 筛出的候选最优组合复现确认（3-4 个候选各 1 次）
3. 官方精度 benchmark 验证（Daily-Omni 等）
4. 正式 RTF 数据采集（提交数据必须出自 910C）

### 衔接
- 4090 参数搜索结果 → 910C 复现 → 若 CANN 性能特征差异大，
  剩余卡时做 1-2 轮二次微调（仅量化档位 + 2-3 个关键参数）

## 风险与预期

- CUDA/CANN 算子实现与量化核性能不同，4090 最优档位未必 910C 最优
  → 预留二次微调卡时
- 预期 910C 用量 20-30 卡时足够（不含排队等待时间）

## GPU1 使用约束（secs 共享机器）

- GPU0/2/3 被他人 vLLM 服务占用，勿动
- GPU1 剩余 ~14.5G：Q4_K_M 全模态 ~9G 可跑；Q8_0 全模态 ~13G 勉强；
  F16 不可跑（~20G）
- 使用前 nvidia-smi 确认显存余量，避免影响他人作业

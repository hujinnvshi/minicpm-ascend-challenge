> 用途：SSH key 配置完成后，在 910C（CANN Lab NPU A3 = Ascend910 双 die 64GB / CANN 9.1.0 / 40 核）

## 使用方法

1. 910C 上启动 agent（Hermes：`hermes`；或 opencode），粘贴上面整段提示词；
   或单次执行：`hermes chat -q "<提示词>"`（注意 shell 引号转义，长文本建议直接进交互式粘贴）
2. agent 会自主完成 探测→补齐→rts→精度A/B→回传；结果贴回本对话，本机立即打包 v8（5 文件）
3. 若中途失败（如模型缺失/构建报错），把报错贴回，本机出修复命令

## 提示词结构说明（以后如何自己改）

| 组成部分 | 为什么这么写 | 要改时动哪里 |
|---|---|---|
| 背景段 | agent 无本机上下文，先交代"现状+本次目的" | 进度数字随测试更新 |
| 阶段 0 探测 | 环境/产物先探明，决定跳过哪些步骤（全新 vs 已有构建都能用） | 路径随仓库位置 |
| 阶段 1 补齐 | 按需拉代码/模型/构建，图模式必须 --graph 构建 | 仓库 URL、构建目标 |
| 阶段 2 rts | 构建变了才需要；验证 FA+batch_validity+RTF 基线 | smoke 数量 |
| 阶段 3 A/B | 核心门禁：同 env 仅 ACL_GRAPH 翻转，指标差 ≤10% | 数据集/样本数 |
| 阶段 4 回传 | 固定格式 → 本机直接对照判读、立即决策 | 回传字段 |
| 红线 | NZ=off / 不可改文件 / 不改数学 / 设备探测 | 官方规则变化时 |

关键设计点：
- **自包含**：所有路径/env/判读标准写全，agent 不需要本机任何上下文
- **状态自适应**：探测先行，已有构建就跳过构建，节省时间
- **门禁写死**：batch_validity 全 true + 差 ≤10%，避免 agent 主观放水
- **A/B 唯一变量**：只翻 ACL_GRAPH，保证对比纯净（零影响验证的强形式）

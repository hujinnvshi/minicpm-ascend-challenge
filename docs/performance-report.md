## 1. 任务与目标

- 模型：MiniCPM-o 4.5（9B 全模态）
- 框架：llama.cpp-omni
- 环境：昇腾 910C 单卡 + CANN 9.1.0-beta1（官方统一评测环境）
- 指标：流式语音生成每音频 chunk 的 RTF（RTF = 生成耗时 ÷ 音频时长，越低越好）
- 约束：精度降幅 ≤2pp（Daily-Omni 等基准）、Demo 可用、可复现

## 2. 优化方法（总体思路）

分两阶段：
1. 本地预实验（NVIDIA RTX 4090，CUDA 后端）——用算力换时间，
   在本地完成量化档位扫描、运行时参数寻优、优化候选筛选，
   建立可复现的评测方法
2. 昇腾 910C（CANN 后端）——复现候选配置、验证图模式等
   CANN 特有优化、采集正式评测数据

优化空间分析：音频 chunk 生成链路 = LLM 解码 → TTS 音频 token 生成
→ Token2Wav 波形合成。RTF 为链上各段耗时之和 ÷ 音频时长。

## 3. 评测方法（标准化）

- 工具：官方 tools/omni/perf（perf-duplex + analyze_perf.py），
  36 帧全双工模拟（SPEAK 12 / LISTEN 24，1s 推帧间隔）
- 硬判据：TTS RTF < 1.0；LLM 判定 P95 < 进帧间隔；首响 e2e P95 < 间隔
- 标准化：每配置 ≥3 次运行取均值；输出内容质量检查
  （llm_debug/llm_text.txt 验证生成内容正常，防量化/后端 bug 假象）
- 环境记录：GPU 状态、温度、并发负载（共享机器影响 RTF ~10%）

## 4. 基线数据

### 4.1 量化档位扫描（4090，ctx 4096）

| 档位 | TTS RTF | 输出质量 | 备注 |
|------|---------|---------|------|
| Q8_0 | 0.32* | ✗ 乱码循环 | *重复 token bug，不可用 |
| Q6_K | 0.75 | ✓ | |
| Q5_K_M | 0.86 | ✓ | |
| Q4_K_M | 0.73 | ✓ | 基准选择 |
| Q4_K_S | 0.86 | ✓ | |
| Q4_0 | 0.87 | ✓ | |

→ 结论：Q4_K_M 为 4090 最优可用档位；Q8_0 因生成 bug 出局
（CANN 后端待重验）；K-quant 系列在 4bit 档位优于非 K 档。

### 4.2 上下文参数（Q4_K_M，标准化 3 次）

| ctx | TTS RTF | 结论 |
|-----|---------|------|
| 4096 | 0.77 | 基线 |
| 8192 | 0.75 | 最优（+2.6%），减少 KV 滑窗触发 |
| 16384 | 0.75 | 饱和 |

### 4.3 无效优化排除（节省他人时间，体现严谨性）

| 尝试 | 结果 | 结论 |
|------|------|------|
| TTS n_ctx 缩容 2048 | 0.75（无提升） | 无效，已回退 |
| -march=native | 0.75（无提升） | 无效 |
| Q6_K × ctx 8192 | 0.77 | 组合无叠加 |

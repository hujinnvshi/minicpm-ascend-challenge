# 910C 理论仿真外推（2026-08-25）— v6 配置 910C 预测排名 + 特性收益上限

> ## 🔄 2026-08-26 校准更新（官方 v5 实测锚定，本节优先于下文全部预测）
>
> **新数据点**：官方 910C v5（8/22 提交）实测 RTF **0.8357**（8/26 回写）。
>
> **校准**：v5 本地 1.3291 → 官方 0.8357 = **同代码加速 1.590x**（vs 下文假设 1.57x，误差 1.3% → 模型可信）。
> ⚠️ 早先"910C 快 28%"（0.8357 vs 本地 v6 1.166）是 v5官方 vs v6本地的**异代码对照**，已修正为 1.59x。
>
> **v6 在 910C 的成绩分布预估**：
>
> | 方法 | 逻辑 | RTF 预估 |
> |---|---|---|
> | 等比法（保守上界） | v6 收益 -12.3% 等比保留：0.8357 × 1.166/1.3291 | **0.733** |
> | 物理法（中枢） | head 并行节省 = CPU 绝对时间（tts 段 -0.142），910C 上 CPU 不缩水 → 0.8357 - 0.142 | **0.694** |
> | 综合 | 中位 **~0.71**；区间 **0.66-0.77**（±0.03 官方 CPU 强弱 + 单次出分噪声 ±3-5%） | **0.69-0.73** |
>
> **排名映射**（沿用下文场景表）：0.71 ≈ 第 4 名档（0.734）；0.66-0.69 摸第 3 边缘；
> 进前 3（<0.609）需 910C 特性（图模式/FP8）加持，纯 env 配置达不到。
> 8/25 预测区间 0.51-0.78 收窄：纯 env 下限应为 ~0.66（0.51/0.61 需特性配合）。
>
> **验证闭环**：v6 出分后与 0.69-0.73 对照——若 <0.66 说明官方 CPU 段更快或评测输入更短；
> 若 >0.77 说明 head 并行收益被更强 CPU 稀释（单核快 → 并行收益降）。

> 背景：无 910C 硬件，优化思路无法实测验证 → 用"参数化外推 + 排行榜校准"做理论仿真。
> 脚本：`scripts/910c-simulation.py`（可复算）。口径：core 帧 pooled RTF。
> ⚠️ 局限：910C 算力/带宽倍率来自公开资料与厂家"1 颗 910C=2 颗 910B"说法（推断级，非官方评测明细）；
> 图模式/FP8 执行引擎行为无法仿真，只能做"如果生效"上限（敏感性分析）。

## 一、输入数据（910B4 v6 实测段耗时）

| 段 | 耗时(s) | 特性分类 |
|---|---|---|
| encode(max VPM/APM) | 0.359 | launch/固定成本主导（~700 op × 0.32ms/op） |
| llm_prefill | 0.017 | 算力敏感 |
| llm_decode | 0.241 | 带宽下限主导（13.7ms/tok，FA 后） |
| tts | 0.275 | CPU head_code(3.1ms/步) + NPU forward(6.9ms/步) 混合 |
| token2wav | 0.257 | NPU Flow + CPU vocoder |
| **Σ（模型）** | **1.149** | 实测 1.166，差 0.017（prefill/取整） |

## 二、校准（910C 真实数据点）

- 910B4 官方默认 RTF = 1.71（2026-08-21 实测）vs 910C 榜尾（NoOneAhead 1.0925，轻优化）
- → **910C vs 910B4 总体加速系数 ≈ 1.57x**（默认配置口径）
- 注意：我们的优化改变段构成（decode 0.57→0.24 带宽主导），段级加速分布 ≠ 默认配置，故场景外推以段级为主、1.57x 缩比作保守下限

## 三、场景外推：v6 配置在 910C 的 RTF 预测

| 场景 | 段加速因子 | RTF_910C | 对应排名 |
|---|---|---|---|
| 悲观（固定成本不减，2x 只作用算力/带宽） | encode 1.3 / decode 1.7 / 其余 1.5 | **0.784** | 第 6 名 |
| 校准缩比（中性×1.57/2.0） | 全局 1.57x | **0.734** | 第 4 名 |
| **中性（2x 算力/带宽全段生效）** | encode 1.8 / decode 2.0 / tts 2.0 / t2w 1.8 | **0.609** | 第 3 名 |
| 乐观（2x + 固定成本减半，8/24 外推先例） | encode 2.4 / tts 2.3 / t2w 2.4 | **0.505** | 第 1 名 |

**预测区间 0.51-0.78，中位 ~0.61-0.73 → 对应排行榜第 3-6 名。进前 5 概率大，冲前 3 需要 910C 固定成本也给力（乐观场景）。**

## 四、910C 特性收益上限（独立生效，910B4 基线 1.149 上叠加）

| 特性 | 机制假设 | RTF 变化 |
|---|---|---|
| **图模式**（VPM launch 摊薄 50%） | ~700op×0.32ms → 0.16ms/op，encode 0.359→0.233 | **-10.9%**（最大单项） |
| FP8 权重（decode 权重带宽 -20%） | 16bit→8bit，decode 40% 权重带宽敏感 | -4.6% |
| Q8 硬件反量化（同 FP8 带宽项） | 910C 反量化单元快（对手量化有效=硬件差异） | -4.6% |
| KV 量化 INT8（decode 带宽 -21%） | decode 60% 带宽敏感，INT8 KV 省 30-40% 读取 | -4.4% |
| **组合全开（上限）** | 以上全生效 | **-19.1%** |

→ 中性 0.609 若叠加组合特性（-19.1%）≈ **0.49** → 榜首水平。**榜首 0.5308 = 910C 2x + 图模式等特性全开的水平**，与我们 8/24 外推先例（0.46-0.55）一致。

## 五、vs 榜首差距分解（中性场景）

| 段 | 我们(910C) | 榜首隐含 | 差距 |
|---|---|---|---|
| encode | 0.199 | 0.15 | **+0.049** |
| tts | 0.138 | 0.12 | +0.018 |
| **token2wav** | **0.143** | **0.07** | **+0.073（最大）** |
| decode | 0.12 | 0.12 | 0 |
| prefill | 0.009 | ~0 | ~0 |
| Σ | 0.609 | 0.46-0.55 | +0.078 |

**主要短板 = token2wav（vocoder）段（+0.073）与 encode/VPM 段（+0.049）**——正是 910C 特性收益区（vocoder 上卡/图模式省 launch）。

## 六、结论与建议
1. **我们的优化（FA/head 并行/NPU 串行）硬件无关，910C 上等比保留**：910B4 -32%（1.71→1.166）在 910C 上同样兑现
2. **预期排名第 3-6**：若官方调度恢复出分，0.6 附近是中性预期；0.53 以下需要 910C 特性配合（图模式等），超出纯 env 优化范围
3. **图模式收益上限最大（-10.9%）但官方评测默认 ACL_GRAPH=off** → 唯一路径 = SUBMISSION_GUIDE §1.2 架构级复核通道（复核期长）；set_acl_graph 接口已就绪
4. **token2wav/vocoder 是 910C 上最大差距项**：910C 若 vocoder 可上卡（CANN CNN 算子）→ 该段 -50%+；本机无法验证，标记"910C 特性待验证"
5. 仿真的验证闭环 = 官方出分：v5/v6 出分后与预测区间对照，校准模型参数（若实际 >0.78 说明 910C 加速低于预期或固定成本更高；若 <0.51 说明 910C 特性被对手广泛使用）
